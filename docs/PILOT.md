# Пилот с операторами и проверка разметки

В репозитории есть синтетические офлайн-результаты и пустые формы исследований. Замеры операторов, интервью и реальные данные школа и команда пока не предоставляли.

## Качественная проверка проблемы

Руководитель сервиса и два оператора описывают текущую схему очередей и оценивают потери на трёх недавних примерах без персональных данных. Команда фиксирует реальные объём входящих, долю волн нагрузки, время маршрутизации и повторные переводы по данным школы. Протоколы интервью хранятся вне Git. В проект публикуются агрегаты по согласованию.

## Разметка

Два участника получают только `pilot/annotation_input.csv` и правила из [описания корпуса](DATA_METHOD.md). Каждый заполняет собственную копию `pilot/annotation_response.csv`. Разметчики не открывают контрольные файлы и экспериментальные ответы. Арбитр фиксирует расхождения и итог, сохраняя оба мнения. Измерьте согласие до обсуждения, отдельно проверьте кейсы смешанных намерений, отрицаний и `other`. Для следующего полноценного замера подготовьте новые фразы, которых не было в репозитории.

## Сравнение двух режимов

1. Сформируйте 24 новых обезличенных текста и попарно уравняйте блоки A и B по очередям, длине, неоднозначности и сложности. До сессии закрепите согласованные эталоны, метрику и критерии исключения.
2. Дайте 4–5 операторам пройти два блока по 12 сообщений. Для первых четырёх используйте порядки: A вручную / B с помощником, B с помощником / A вручную, A с помощником / B вручную, B вручную / A с помощником. Пятому назначьте порядок заранее. Каждый видит сообщение один раз. Случайно перемешайте порядок внутри блоков с сохранением списка.
3. В обоих режимах используйте одинаковый список очередей и ручного разбора. В ручном режиме скройте рекомендации и оценки. Начинайте таймер при первом показе текста, завершайте при выборе очереди. Паузы и сбои отмечайте отдельным полем. Тренировочные кейсы исключайте из обоих блоков.
4. Запишите секунды, итоговую очередь, наличие подсказки, эталон, ошибки и прерывания в [pilot_log.csv](pilot/pilot_log.csv). Учитывайте вручную исправленные подсказки и ошибочные подтверждения по отдельности.
5. Сравните у каждого оператора медианное и среднее время, ошибки и изменение между режимами. Покажите результаты раздельно для верной подсказки, ошибки модели и отказа. Для итоговой оценки долей покажите числители, знаменатели и интервалы. При 4–5 участниках выводы остаются предварительными.
6. Подставьте фактические времена и выполнимую долю монетизации в калькулятор. Если ограничения по неправильным подсказкам или итоговым ошибкам не выполняются, проведите новый цикл выбора порога на свежем validation и новый слепой тест.

Идентификаторы операторов замените псевдонимами. Тексты реальных клиентов требуют согласованного безопасного хранения. До этого используйте только синтетические сообщения.
