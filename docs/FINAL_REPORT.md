# Итоговый отчёт Первого ответа

Локальный MVP на ветке `development-v2` выполняет сквозной сценарий от поступления текста до решения оператора, истории и аналитики. Исходная версия сохранена на `main` и под тегом `baseline-v1` (`f78760d`). Оригинальный DOCX повторно сверён и имеет исходный SHA-256. [Матрица задания](REQUIREMENTS_MATRIX.md).

## Что требовалось и что изменилось

По заданию требуются коммуникационный MVP с ИИ, данные и тестовые метрики, количественная связь с бизнесом, бюджет и окупаемость, доступный Git и защита 10–15 минут. В исходном прототипе работал локальный классификатор. Решения оставались в браузере, порог был фиксирован, сравнения и автоматизированных тестов не было, расчёт монетизировал всё высвобождённое время.

| Область | AS-IS | TO-BE, проверено в v2 |
| --- | --- | --- |
| Обращение | Один текст и визуальное подтверждение | Входящие, поиск и фильтры, импорт CSV, решения, история и восстановление после перезапуска |
| Аналитика | Результаты в README | Операционные счётчики из SQLite, отчёт качества из эксперимента и интерактивная экономика |
| Данные | 120 train и 120 test, синтетика | Train 245, Validation 75, Test 90, Challenge 60 и Benchmark 90. Синтетика с происхождением и аудитом семейств |
| Модель | Символьный TF-IDF + LogReg, порог 0,60 | Сравнение правил, v1 и трёх ML-моделей. Выбран Naive Bayes с порогом 0,55 на validation |
| Риск | Единый отказ по порогу | Причины отказа, тест неизвестных и сложных формулировок, итог сохраняет оператор |
| Экономика | Один прогноз при 100% монетизации | Три сценария, 13 входов, FTE, окупаемость, ROI, безубыточность и чувствительность |
| Верификация | Ручной показ | 20 автоматизированных тестов, браузерный сценарий на двух ширинах, чистая локальная копия |
| Защита | Текстовый сценарий | 8 слайдов с заметками, живой показ на 14 минут с вопросами, формы пилота и декларация |

Решение оставить Python, scikit-learn, SQLite и статический фронтенд сохранило автономный запуск. База хранит текст, снимок рекомендации, версию модели и отдельное решение, обновляет журнал транзакционно и защищает от перезаписи устаревшей карточкой. Фактического подключения к школе в MVP нет. [Аудит исходного состояния](TECHNICAL_AUDIT.md) · [Тестовые доказательства](TEST_REPORT.md).

## Что подтверждено экспериментами

Исходный результат совпал с заявленным на исходном тесте: 61/63 верных подсказок, 52,5% охвата, Macro-F1 кандидата на четырёх очередях 0,9175. Исходный экономический прогноз 21 667 ₽ и 4,15 месяца повторился при прежних допущениях. [Контрольный замер](ML_BASELINE.md).

| Метрика на одном новом тесте из 90 строк | Исходная v1 | v2 |
| --- | ---: | ---: |
| Охват | 55,6% | 74,4% |
| Точность выданных подсказок | 98,0% | 89,6% |
| Верные подсказки | 49 | 60 |
| Ошибочные подсказки | 1/90 | 7/90 |
| Ручной разбор | 44,4% | 25,6% |
| Macro-F1 итоговых решений с классом отказа | 0,7588 | 0,7993 |
| Macro-F1 кандидата на четырёх целевых очередях | 0,9167 | 0,9301 |
| Доля отказов на `other` | 17/18 | 11/18 |
| Расчётное время с помощником | 62,11 с | 54,89 с |
| Чистый прогноз при одинаковой монетизации 65% | 12 170 ₽/мес. | 18 430 ₽/мес. |

v2 дала больше верных подсказок на общем тесте с ростом доли ошибок. Порог не выдержал ориентир 6% на итоговом тесте. Логистическая регрессия показала более высокий Macro-F1 на этом тесте, а правила и v1 допустили меньше ошибочных рекомендаций. Выбор модели сохранён по validation. Brier и ECE на итоговом тесте выросли после калибровки. Ни одна цифра качества и времени из синтетического эксперимента не измеряет результаты реальных операторов. [Метрики, интервалы и ошибки](ML_EXPERIMENT.md).

В базовом сценарии у v2 расчёт 58,5 ч и 0,366 FTE в месяц, 4,88 месяца простой окупаемости и 56,0% ROI первого года. Пессимистичный сценарий даёт отрицательный эффект и не окупается. Длительности и монетизация требуют пилотных замеров. [Экономическая модель](ECONOMICS.md).
