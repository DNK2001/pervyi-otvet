# Корпус и правила разметки

Все тексты в репозитории синтетические. Исходные наборы `data/train.csv` и `data/test.csv` сохранены отдельно и не изменялись. Наборы v2 собраны из тематических блоков, написанных с помощью OpenAI Codex, с явным указанием варианта происхождения в поле `source`. В них нет записей службы поддержки или замеров пользователей.

| Набор | Строки | Роль | Происхождение |
| --- | ---: | --- | --- |
| Исходный train / test | 120 / 120 | Воспроизведение v1 | Исходные синтетические CSV |
| Train v2 | 245 | Обучение и калибровка на сгруппированных фолдах | 125 новых и 120 исходных тренировочных сообщений |
| Validation | 75 | Выбор модели и порога | По 15 сообщений на класс |
| Benchmark | 90 | Диагностика после первого прогона | По 18 на класс. В первом прогоне назывался test |
| Test | 90 | Итоговая оценка зафиксированного протокола | По 18 на класс. Прогнозы впервые рассчитаны после фиксации протокола в Git |
| Challenge | 60 | Диагностика по типам сложных формулировок | По 10 на каждую очередь, 20 иных или неоднозначных. Использовался для диагностики в первом и втором прогонах |

## Сборка и контроль пересечений

`data/v2/source/*.txt` содержит сообщения, уникальные названия сценарных семейств и метки. В `legacy_families.txt` указано текстовое сопоставление строк исходного Train с семействами v2. `dataset.py` собирает CSV с идентификаторами, сохраняет источник и проверяет поля. Для калибровки группы не расходятся между обучающей и проверочной частями одного фолда. Разбиение по семействам устраняет повторения одного сценарного блока и не исключает совпадение общих терминов очереди.

Аудит ищет точные копии после нормализации и межвыборочные Jaccard-сходства по символьным 4-граммам от 0,60. Максимум для всех пар Train/Validation/Benchmark/Test/Challenge составил 0,323. Это проверка лексического сходства, семантические дубли могут иметь низкий Jaccard. Диалоги независимо проверяют участники пилота. Хеши и ближайшие пары приведены в [результатах](experiments/v2.json).

Примеры создавались как отдельные обращения. В тексты входят короткие и развёрнутые сообщения, разговорные формулировки, опечатки, отрицания, эмоции, смешанные намерения, неинформативные реплики, неизвестные темы и нерелевантные сообщения. Проект рассмотрел корпус 1 000–2 000 строк. При отсутствии согласованных реальных текстов масштабирование одним генератором сосредоточило бы больше однотипных формулировок. Для задачи полезнее следующая независимая партия, размеченная командой.

## Инструкция для разметчика

1. Прочитать обращение целиком и сформулировать главное требуемое действие своими словами. Тема упомянутого существительного может быть фоном.
2. Выбрать очередь по действию. `access` — восстановление входа или профиля. `payment` — платёж, возврат, квитанция и денежные операции. `schedule` — согласование времени, даты или посещения занятия. `materials` — получение записи, файла, задания или учебного ресурса.
3. При нескольких темах искать явный приоритет, причину обращения и последовательность действий. «В кабинет вошла, а файл пустой» — `materials`. «Восстановите вход, запись посмотрю потом» — `access`.
4. Помечать `other`, если нет достаточного контекста, есть две самостоятельные просьбы равного приоритета или обращение вне четырёх очередей. Примеры вне области включают предложения о партнёрстве, апелляции, вакансии и отзывы.
5. Сначала два участника размечают независимо. Скрыть подсказки и эталонную метку. Затем сверить расхождения, сохранить обе исходные метки и решение арбитра. Измерить долю согласия и κ Коэна до арбитража. Решение оператора из интерфейса остаётся обратной связью.

Отрицание причины отличается от отрицания результата. «Оплата ни при чём» исключает очередь оплаты. «Оплата не прошла» описывает сбой оплаты и относится к этой очереди. Правила проверяются на нескольких представителях каждой очереди, а спорные случаи уточняются перед следующей версией разметки.

Пакет для независимой ручной проверки есть в [annotation_input.csv](pilot/annotation_input.csv). В [annotation_response.csv](pilot/annotation_response.csv) оставлены пустые поля. Команда копирует его для каждого разметчика. Сценарий оценивания и журнал фактических измерений описаны в [PILOT.md](PILOT.md).
