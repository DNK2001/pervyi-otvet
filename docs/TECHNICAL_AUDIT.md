# Технический аудит исходной версии

| Наблюдение | Свидетельство в baseline-v1 | Последствие |
| --- | --- | --- |
| Размер процесса и длительности условны | README, раздел «Экономический сценарий» | Утверждения о денежном эффекте возможны только как прогноз |
| По 120 синтетических строк, нет validation | `data/train.csv`, `data/test.csv`, `evaluate.py` | Оценка чувствительна к стилю генерации и составу теста |
| Единственный оценённый классификатор | `triage.py:23–37` | Причины выбора модели нельзя проверить сравнительным экспериментом |
| Слабая проверка отрицаний, смешанных целей и незнакомых тем | Нет отдельного стресс-теста, две ошибки `other` в исходной оценке | Требуется отдельный замер на сложных формулировках |
| Порог 0,60 и некалиброванные оценки | `triage.py:14,40–53` | Порог не связан с ценой ошибочной подсказки. Проценты легко принять за вероятность |
| Потеря решений после обновления | `static/app.js:151–155` только меняет текст в DOM | Невозможно проверить историю, статусы и повторный запуск |
| Сценарий только для одного текста | `app.py`, одна операция API | Нет входящих, поиска, пакетной обработки и аналитики |
| Нет автоматизированных проверок | Список файлов коммита | Ручное демо не проверяет граничные случаи и сохранность |
| API и зависимости простые | `http.server`, закреплённый `requirements.txt` | Стек пригоден для локального MVP. Для общей сети нужны другой контур доступа и эксплуатационные проверки |

Аудит зафиксировал исходный текст справки, UI, правила валидации HTTP и расчёты. Исходные `evaluate.py` и `economics.py` сохранены для повторения исторического замера.
