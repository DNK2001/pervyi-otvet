# Первый ответ

«Первый ответ» помогает оператору первой линии поддержки онлайн-школы выбрать очередь для русскоязычного обращения. Модель предлагает одну из четырёх очередей. Если её максимальная оценка ниже 0,60, интерфейс предлагает ручной разбор. Оператор всегда сам выбирает окончательную очередь. В MVP подтверждение отображается в браузере, интеграция с системой поддержки в расчёте относится к этапу внедрения.

## Запуск

Нужен Python 3.11–3.13. Сценарий проверен на Python 3.13.7. Команды выполняются из каталога проекта. Первый запуск в новом окружении требует установки библиотек. После установки демонстрация работает локально без сети, облачных сервисов и ключей.

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -B -X utf8 app.py
```

macOS / Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -B -X utf8 app.py
```

Откройте [локальное приложение](http://127.0.0.1:8000). Если порт занят, добавьте к команде запуска `--port 8001` и откройте адрес с новым портом. Для остановки нажмите Ctrl+C.

1. Нажмите **Возврат денег**, затем **Определить очередь**. Модель предложит «Оплата и возврат». Нажмите **Подтвердить** или выберите другую очередь перед подтверждением.
2. Нажмите **Партнёрство** и запустите анализ. Модель предложит ручной разбор.
3. Введите своё русскоязычное сообщение длиной до 1000 символов. Сравните оценки модели и выберите итоговую очередь.

Для повторения замера и расчёта используйте Python из созданного окружения. Например, в Windows выполните:

```powershell
.\.venv\Scripts\python.exe -B -X utf8 evaluate.py
.\.venv\Scripts\python.exe -B -X utf8 evaluate.py --json
.\.venv\Scripts\python.exe -B -X utf8 economics.py
.\.venv\Scripts\python.exe -B -X utf8 economics.py --coverage 0.35 --precision 0.90
```

## Область применения

Пользователи продукта — операторы первой линии. Модель внедрения охватывает одну онлайн-школу с 5 000 активных учащихся. При 1,2 обращения на учащегося в месяц процесс обрабатывает 6 000 сообщений. Эти допущения описывают масштаб одного внедрения и требуют замера у конкретной школы.

Ключевая бизнес-метрика — среднее активное время оператора от чтения входящего текста до подтверждения очереди, включая исправление ошибочной подсказки. Время ожидания в очереди и время решения вопроса специалистом в метрику не входят.

## Данные и разметка

[Обучение](data/train.csv) содержит 120 синтетических обращений, по 30 на каждую очередь. [Тест](data/test.csv) содержит 120 других синтетических обращений, по 24 на каждую очередь и отдельный класс `other`. Тест составлен отдельным проходом без просмотра обучающих текстов, с опечатками, разговорными формулировками и запросами на стыке тем. При сопоставлении без учёта регистра, пунктуации, «ё» и лишних пробелов совпадений между выборками не обнаружено. Каждая строка имеет поля `text` и `label`. Оба набора созданы при помощи генеративного ИИ. В них нет обращений реальных клиентов.

| Метка | Очередь | Как ставится метка |
| --- | --- | --- |
| `access` | Доступ и аккаунт | Вход, пароль, профиль или восстановление аккаунта |
| `payment` | Оплата и возврат | Платёж, чек, списание или возврат денег |
| `schedule` | Расписание занятий | Время, дата, перенос или отмена занятия |
| `materials` | Учебные материалы | Записи уроков, файлы, задания или их доступность |
| `other` | Ручной разбор | Партнёрство, сертификаты, организационные и другие вопросы вне четырёх очередей |

У смешанного обращения метку задаёт основное запрошенное действие. Если ученик вошёл в аккаунт, но не видит запись урока, это «Учебные материалы». Если он просит восстановить вход, чтобы затем посмотреть запись, это «Доступ и аккаунт». В полевом пилоте спорные случаи нужно независимо разметить двумя участниками команды и разобрать расхождения до оценки модели.

Перед обучением и прогнозом применяются нормализация Unicode NFKC, приведение регистра, замена «ё» на «е» и нормализация пробелов. Словарь признаков и веса TF-IDF строятся только на обучении. Тест не используется для подбора порога или обучения.

## Модель и выбор инструментов

Модель обучается при старте приложения. Символьный TF-IDF учитывает последовательности из 3–5 соседних символов внутри слов с пробелами по краям. Например, часть «оплат» встречается в «оплату» и «оплата», поэтому формы слова могут иметь общие признаки. Логистическая регрессия присваивает каждому маршруту оценку. Если самая высокая оценка ≥ 0,60, модель показывает подсказку. Порог 0,60 зафиксирован до теста. Оценка модели не откалибрована и не равна доле правильных ответов.

Локальный scikit-learn выбран из-за небольшой обучающей выборки, четырёх фиксированных классов и возможности обучиться и сделать прогноз на обычном CPU. Это исключает расходы на запросы к облачному API и позволяет выполнить демо автономно. Поиск по ключевым словам проще обслуживать, но для него нужно вручную поддерживать варианты формулировок и решать конфликты правил. Сравнительный замер с таким методом в MVP не проводился. Большая языковая модель добавила бы вычислительные затраты на задачу, где выход ограничен выбором очереди.

Локальный пробный замер после импорта библиотек дал ≈0,07 с на обучение и ≈0,49 мс медианного времени одного тёплого вызова модели на коротких текстах. В замер не входят запуск Python и запрос по HTTP. Для внедрения закладываем один внутренний экземпляр с ориентиром 1 vCPU и 1 ГБ RAM. Пиковую нагрузку и задержку предстоит измерить в пилоте.

Технические источники: [TfidfVectorizer](https://scikit-learn.org/1.7/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html), [LogisticRegression](https://scikit-learn.org/1.7/modules/generated/sklearn.linear_model.LogisticRegression.html), [F1](https://scikit-learn.org/1.7/modules/generated/sklearn.metrics.f1_score.html).

## Замер на тесте

| Метрика | Результат |
| --- | ---: |
| Охват подсказками | 63 из 120 · 52,5% |
| Верные среди подсказок | 61 из 63 · 96,8% |
| Верные подсказки среди всех обращений | 61 из 120 · 50,8% |
| Точность кандидата внутри четырёх очередей до порога | 88 из 96 · 91,7% |
| Macro-F1 кандидата на четырёх очередях до порога | 0,9175 |
| Обращения вне маршрутов, ушедшие на ручной разбор | 22 из 24 · 91,7% |

Macro-F1 — среднее F1 четырёх очередей с одинаковым весом для каждой. Он измеряет выбор лучшего класса до применения порога на 96 обращениях внутри четырёх очередей. Для операционной оценки берём все 120, включая `other`. Охват считает, как часто модель предлагает очередь. Доля верных среди подсказок считает, как часто предложенная очередь совпадает с эталоном.

| Истинная метка | Доступ | Оплата | Расписание | Материалы | Ручной разбор |
| --- | ---: | ---: | ---: | ---: | ---: |
| Доступ | 19 | 0 | 0 | 0 | 5 |
| Оплата | 0 | 13 | 0 | 0 | 11 |
| Расписание | 0 | 0 | 16 | 0 | 8 |
| Материалы | 0 | 0 | 0 | 13 | 11 |
| Вне маршрутов | 0 | 1 | 1 | 0 | 22 |

Две ошибочные подсказки относятся к вопросам вне маршрутов. Обращение о сертификате для портфолио попало в оплату, а вопрос об индивидуальной сдаче проекта — в расписание. Порог отсеял восемь ошибочных кандидатов среди 96 целевых обращений, вместе с ними ушли в ручной разбор и 27 верных кандидатов. Результат на синтетических сообщениях показывает работоспособность сценария. В реальном потоке доля каждой темы и число обращений вне маршрутов могут отличаться, поэтому охват, точность подсказок и денежный эффект нужно измерить заново.

## Экономический сценарий

### Допущения

| Входной параметр | Значение |
| --- | ---: |
| Входящие обращения | 6 000 в месяц |
| Ручной выбор очереди до внедрения | 90 с |
| Обработка при верной подсказке | 30 с |
| Обработка при ошибочной подсказке | 120 с |
| Ручной разбор после отказа модели | 100 с |
| 1 FTE | 160 рабочих часов в месяц |
| Полная стоимость часа оператора | 800 ₽ |

В 120 секундах заложено время проверки и исправления ошибки, в 100 секундах — ручной разбор плюс дополнительный шаг в интерфейсе. Значения для трёх исходов и текущего процесса условны. Для пилота их нужно измерить от начала чтения до подтверждения очереди.

### Связь показателей модели и времени

Пусть `c` — охват подсказками, а `p` — доля верных среди подсказок. Тогда ожидаемое время с помощником в секундах:

```text
T = c × (p × 30 + (1 − p) × 120) + (1 − c) × 100
T = (61 × 30 + 2 × 120 + 57 × 100) / 120 = 64,75 с
```

При таком же охвате 52,5% снижение точности подсказок на 10 п. п. добавит 4,73 с на обращение: `0,525 × 0,10 × (120 − 30)`. Это 7,88 часа или 6 300 ₽ меньшего эффекта в месяц при заданном объёме. Снижение порога может повысить охват и одновременно ухудшить точность, поэтому для сравнения порогов нужно передать в формулу оба измеренных показателя.

### Результаты и затраты

| Показатель | Значение |
| --- | ---: |
| Время на обращение | 90,00 → 64,75 с, снижение на 28,1% |
| Нагрузка первой линии на выбор очереди | 150,0 → 107,9 ч/мес. |
| Нагрузка в FTE | 0,94 → 0,67 |
| Ресурс для перераспределения | 42,1 ч/мес. · 0,26 FTE |
| Валовая стоимость высвобожденного времени | 33 667 ₽/мес. |
| Разработка и внедрение | 90 000 ₽ единовременно |
| Эксплуатация | 12 000 ₽/мес. |
| Эффект за вычетом эксплуатации | 21 667 ₽/мес. |
| Простая окупаемость при стабильных объёмах | 4,15 месяца |
| Эффект за первый год за вычетом всех затрат | 170 000 ₽ |
| ROI первого года | 72,6% |

Сумма внедрения включает 50 ч разработки, 25 ч интеграции и 15 ч подготовки данных и проверки по 1 000 ₽/ч. В эксплуатации 8 000 ₽/мес. заложено на 8 ч поддержки и контроля качества, ещё 4 000 ₽/мес. — резерв внутренней инфраструктуры. Эти суммы — бюджетные допущения. Цена использования модели за один локальный запрос не тарифицируется.

Для второй школы сопоставимого размера при повторном использовании кода заложены ещё 25 ч интеграции и 15 ч подготовки данных и проверки, всего 40 000 ₽. Отдельный экземпляр и сопровождение добавят 12 000 ₽/мес. Суммарный бюджет двух внедрений при 12 000 обращений в месяц составит 130 000 ₽ единовременно и 24 000 ₽/мес. Качество и пиковую нагрузку для второй школы нужно измерить отдельно.

Валовая оценка равна `(90 − 64,75) × 6000 / 3600 × 800`. Окупаемость равна `90000 / (33666,67 − 12000)`. Годовой ROI равен `(12 × 33666,67 − 90000 − 12 × 12000) / (90000 + 12 × 12000)`. Прогноз предполагает стабильный объём и полное использование высвобожденных часов на других задачах. Операционная ёмкость в 0,26 FTE отражает долю рабочей нагрузки. Она станет денежной экономией только при фактическом сокращении оплачиваемых часов или предотвращении найма.

При охвате 35% и 90% верных подсказок прогноз равен 78,65 с, 18,9 ч высвобождения в месяц и ROI первого года −22,4%. Пример показывает, как смещение реального потока или более низкое качество меняет решение о внедрении.
