# Первый ответ

Локальный MVP для первой линии поддержки онлайн-школы. Он сохраняет входящее обращение, предлагает одну из четырёх очередей или объясняет отказ. Оператор подтверждает подсказку, меняет очередь или ставит обращение на ручной разбор. Решение, версия модели и история действий сохраняются в SQLite.

Модель помогает сократить время выбора очереди. Сценарий одного внедрения предполагает 5 000 активных учащихся и 6 000 обращений в месяц. Этот масштаб, времена маршрутизации и затраты предстоит проверить в пилоте.

## Быстрый запуск

Нужен Python 3.11–3.13. Проверено на macOS 15.7.3 ARM64 и Python 3.12.7. Фиксированные колёса NumPy и SciPy для ARM64 macOS требуют macOS 14 или новее. Для установки библиотек нужен доступ к Python Package Index. После установки запуск и проверка работают локально.

macOS / Linux

```bash
python3 --version
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -B app.py
```

Если `python3 --version` показывает системный Python 3.9, создайте окружение доступным Python 3.11, 3.12 или 3.13. На Mac, где проверялся проект, Python 3.12 доступен как `/opt/anaconda3/bin/python3`.

Windows PowerShell

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -B app.py
```

Откройте [приложение](http://127.0.0.1:8000). Для другого порта добавьте `--port 8001`. SQLite-файл по умолчанию создаётся в `var/tickets.sqlite3`. Для чистой демонстрации используйте отдельный путь, например `--db var/defense.sqlite3`. Остановите сервер сочетанием Ctrl+C.

## Сценарии демонстрации

1. В «Обращениях» нажмите **Загрузить демо**. Откроется пример двойного списания. Проверьте подсказку «Оплата и возврат», затем нажмите **Подтвердить подсказку**.
2. Найдите по тексту «партнёрство» или «Срочно!». Прочитайте объяснение и нажмите **На ручной разбор**. В примере про методичку можно выбрать «Учебные материалы» вручную.
3. Откройте **Историю** и журнал действий карточки. Обновите страницу или запустите сервер с той же БД повторно. Сохранённые статусы и решения останутся доступны.
4. Создайте обращение вручную или загрузите CSV в UTF-8 с колонкой `text`. Поддерживаются запятая, точка с запятой и значения в кавычках. Один импорт содержит до 100 обращений по 1 000 символов. Выгрузка учитывает текущие фильтры.
5. Сравните источники «Без демо» и «Только демо» в **Аналитике**. В **Качестве ИИ** переключите итоговый тест и стресс-тест. В **Экономике** выберите сценарий и измените долю монетизации, чтобы увидеть разницу между часами и рублями.

## Архитектура

| Компонент | Что делает |
| --- | --- |
| `app.py` и `static/` | Локальный HTTP API и интерфейс без сборки фронтенда |
| `model.py` и `config/` | Обучение на CPU, оценки, порог, ручной разбор и паспорт версии |
| `storage.py` | SQLite, статусы, транзакции, журнал и операционная аналитика |
| `ticket_io.py` | Валидация текста, импорт и экспорт, синтетическое демо |
| `dataset.py`, `experiment.py`, `docs/experiments/` | Сборка корпуса, выбор модели, тест и сохранённые артефакты |
| `business.py` | Сценарный расчёт и чувствительность |
| `triage.py`, `evaluate.py`, `economics.py` | Воспроизводимый исходный эксперимент v1 |

Сервер слушает loopback. Он ограничивает размеры запроса, использует параметризованные SQL-запросы и показывает пользовательский текст через DOM-свойство `textContent`. Рекомендация хранится вместе с решением и состоянием карточки, обратная связь остаётся отдельной записью. Повторный импорт с тем же ключом безопасен. При конкурентном выборе очередь обновляется только по актуальной ревизии. В базе текст хранится открытым для пользователя Mac. Авторизация, резервное копирование, интеграция с CRM и эксплуатационное тестирование нужны для работы с реальными данными.

## Результаты и экономика

Train 245, Validation 75, итоговый Test 90, Stress 60, дополнительный Benchmark 90. Все сообщения синтетические. На validation выбран TF-IDF + Naive Bayes, порог 0,55. Итоговый тест дал 60 верных из 67 подсказок при охвате 74,4%. Macro-F1 итоговых решений модели 0,7993. Ошибки в потоке составили 7/90, или 7,8%, при validation-ориентире 6%. Калибровка ухудшила Brier и ECE на итоговом тесте. Оценки показывают относительный результат модели для входного текста. Надёжность на реальном потоке открыта. [Данные](docs/DATA_METHOD.md) · [Эксперимент](docs/ML_EXPERIMENT.md).

При 6 000 обращений, 800 ₽/ч, 65% монетизации, 90 000 ₽ внедрения и 12 000 ₽ ежемесячных расходов базовый прогноз даёт 54,9 с вместо 90 с на обращение. Высвобождение 58,5 ч, или 0,366 FTE. Чистый прогноз 18 430 ₽ в месяц, 4,88 месяца до окупаемости, ROI первого года 56,0%. Это расчёт с условными входами. [Экономическая модель](docs/ECONOMICS.md) · [План пилота и формы](docs/PILOT.md).

## Воспроизведение и тестирование

```bash
.venv/bin/python -B -m unittest discover -s tests -v
.venv/bin/python -B dataset.py
.venv/bin/python -B experiment.py
.venv/bin/python -B evaluate.py --json
.venv/bin/python -B economics.py
```

Две последние команды воспроизводят baseline. Для итогового сценария откройте «Экономику» или прочитайте `economics` в `docs/experiments/v2.json`. В Windows используйте Python из `.venv\Scripts`. Браузерная проверка и повторный запуск из чистой копии описаны в [отчёте](docs/TEST_REPORT.md).
